# Latency of the live tutor

How fast the tutor reacts after the student finishes a line, and how it behaves while an AI answer is on its way.
The table below is regenerated by `packages/frontend/tests/latency.spec.ts` (headless Chromium, real Excalidraw canvas, real pointer and keyboard
events, the bridge mocked where an AI answer is involved). Every time is milliseconds from the student's last input event (Escape, pen-up or click)
to the DOM change, taken inside the page with `performance.now()`. Targets: handwritten ✓ around 450 ms after the last pen-up; handwritten ✗ and negative comments no sooner than 2400 ms. Typed feedback stays below 800 ms.

The comment waited for a fixed debounce of 1100 ms (live) or 2200 ms (at the end) after every change.

## What changed

- **Pause instead of a fixed debounce.** `activity.ts` follows the pen (pointerdown/up on the board) and the keys typed into the text editor with
  document-level listeners. A typed line is finished 220 ms after Escape / Ctrl+Enter / a click elsewhere, a correct pen-written line 450 ms after the
  pen lifts, an incorrect line and its negative comment only after 2400 ms; a pen that is down never finishes a line, and a second stroke inside the pause restarts it, so "5 + 2 =" is not judged before the next
  digit is written. The coach timer re-checks the pause when it fires (`App.tsx`).
- **Immediate feedback.** The mascot reacts to the pen at once: it watches (eyes and pencil follow the last stroke through CSS variables, no React
  re-render), after the lift it shows the "checking" dots, the verdict mark is painted on (✓ wipes in, ✗ adds a short shake).
- **Asymmetric verdicts.** `settled.ts` independently settles ✓ and ✗. Pen-down invalidates the settled stroke version immediately, so neither
  an old mark nor a pending correction can return at pen-up before its new quiet window. The negative bubble and teacher corrections are also
  retracted when writing starts; ongoing speech is cancelled. Coach decisions are computed from live state at the deadline, not cached while a
  partial line is on the board. Pen-up re-arms the coach even if a busy stroke interrupted its previous timer.
- **Last-stroke regression.** `ink-round8.spec.ts` exercises 700/1800 ms pauses before the last digit and a fast final zero during the teacher-note
  animation. The existing live-scene preservation in `Board.tsx` remains intact; no stale scene is written over an in-progress stroke.
- **No needless blocking.** An explicit request (menu, chip, chat) is no longer ignored because a text editor happens to be open, and an AI answer
  is no longer thrown away when an editor is open (only a pen stroke in progress makes it obsolete). A chat answer even survives a change of the
  board (its board actions are skipped when the board moved on, the text is kept).
- **No Web Worker.** The check of 20 lines (`checkSteps`) takes about 0.15 ms and the coach decision about 0.02 ms (Node 22, 200 runs, `packages/shared`).
  A worker would add a message round trip that is slower than the check itself.
- **AI requests.** The thinking state is visible in about 5 ms (mascot with dots, bubble "Přemýšlím…" with animated dots and a "Zrušit" button), after
  12 s the bubble says it is still working, a request is abandoned after 90 s. Cancel aborts the HTTP request and calls the bridge's cancel endpoint.

## What is not done

- **Streaming of the answer text** is not implemented. The bridge's providers (CLI of Claude and Codex, Gemini REST in one piece) hand back one
  validated JSON object, and the documented SSE endpoint (`BRIDGE_API.md`) has no server side. The app therefore shows the thinking state and the
  answer as soon as it arrives (the bubble then writes it out progressively).
- **Real AI latency** depends on the provider (seconds to tens of seconds) and is not measured here; the mock answers after 1500 ms.

## Verification (2026-11-07)

Headless Chromium, isolated worktree, `PLAYWRIGHT_PORT=5360`. Handwriting measurements use real fixture strokes through CDP pen events, including
local recognition and DOM rendering. Each handwriting row currently represents one measured run, not a statistical performance benchmark.
The timing tests require ✓ in 440–850 ms and ✗ in 2390–3000 ms; the negative-feedback test holds the pen down for 2600 ms and verifies that
both ✗ and the wrong bubble disappear within 200 ms and stay hidden, including the first 500 ms after the next pen-up.

Reproduce: `PLAYWRIGHT_PORT=5360 npm run test:e2e -w packages/frontend -- tests/latency.spec.ts tests/ink-round8.spec.ts` (PowerShell: set `$env:PLAYWRIGHT_PORT='5360'` first).
